# UsageMon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a lightweight Windows overlay showing Claude/Codex allowance usage, resets, and system metrics, published at harisbashir/usagemon.

**Architecture:** A dependency-free .NET core handles parsers and display state. WPF owns the overlay and Windows APIs; a Codex stdio client and a Claude PowerShell bridge supply usage.

**Tech Stack:** .NET 10, C#, WPF, Windows Forms tray, PowerShell, xUnit, GitHub Actions.

**Spec:** docs/superpowers/specs/2026-10-27-usagemon-design.md

## Global Constraints

- Native C# / WPF application; supported Windows 10/11 desktop systems using .NET 10 WPF.
- Floating, always-on-top widget that can be placed over the taskbar.
- CPU and RAM sample every two seconds; countdown rendering every second; Codex polling every 60 seconds.
- No inference calls, token persistence, undocumented subscription endpoints, or invented missing-window values.
- Claude stale after five minutes; failed Codex refresh preserves its snapshot and visibly marks it stale.

## Review Focus

- Weekly-only and reversed Codex windows must be mapped by duration, never position.
- Corrupt settings and bridge snapshots must not crash the widget or erase a prior valid snapshot.
- Concurrent RPC, broken pipes, timeout, and cancellation must release the child process.
- Monitor removal and non-100% DPI must keep the widget accessible and taskbar placement usable.
- Existing Claude status lines must never be overwritten automatically, and bridge output must contain no conversation data.
