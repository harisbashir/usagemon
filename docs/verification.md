# UsageMon verification

## v0.2.0

Implementation commit: `5a075d29b72bdc726751a088ed5f7e3609a09a1c`.

[Windows CI run](https://github.com/harisbashir/usagemon/actions/runs/40471145246), October 27, 2026: **passed**.

- Core suite: **45 passed**, including Claude settings backups, unrelated-property retention, legacy upgrades, custom status-line protection, invalid/duplicate JSON rejection, and exclusive settings transactions. Windows also verifies that replacing the settings file is denied while it is locked.
- Native Windows suite: **3 passed**, covering metrics, compact monitor placement, and installing/running the embedded Claude helper with PowerShell.
- Claude bridge fixtures passed on Windows PowerShell 5.1 and PowerShell 7.
- Release solution cross-build: zero warnings and errors. Both self-contained and framework-dependent standalone EXEs and ZIPs published successfully on Windows.
- The actual self-contained release EXE was copied into a clean folder without scripts, launched, found by its visible tool-window handle, and measured at **520 logical pixels**. This test caught and verified the correction of the progress bars' binding mode.
- Downloaded CI archives passed integrity checks. Each loose EXE matches its ZIP's executable byte-for-byte, and each ZIP contains the current helper.

Settings changes use an exclusive file handle through read, backup and commit to prevent concurrent writes or replacement on Windows. An exact backup is made before modification, and in-process write failures attempt rollback. The helper itself installs atomically. This is an intentional choice over an unlocked replacement that could lose concurrent Claude settings changes.

Interactive taskbar controls, visual readability across actual fonts/scales, mixed-DPI transitions, and resume behavior still require the [manual smoke checklist](manual-smoke-test.md). Automated startup and width verification do not establish every desktop scenario.

## v0.1.0

Implementation commit: `d6caf21dd65a1428e674cbdec1309b050480bddf`.

[Windows CI run](https://github.com/harisbashir/usagemon/actions/runs/40466363018), October 27, 2026: **passed**.

- Release solution build: zero warnings and errors.
- Core, parser, freshness, placement geometry, settings, and real stdio fixture tests: **33 passed** on both Linux and Windows.
- Native Windows metrics and basic WPF monitor placement/topmost-style tests: **2 passed** on Windows.
- Claude bridge fixtures: passed on Windows PowerShell 5.1, PowerShell 7 on Windows, and PowerShell 7 on Linux. Checks include privacy filtering, zero usage, malformed input retention, repeated atomic updates, pipeline input, and preserving an existing status line's output.
- An installed, subscription-authenticated Codex CLI accepted an actual `initialize` handshake and read-only `account/rateLimits/read`, returning 300-minute and 10080-minute windows. No inference was requested and no credentials were extracted.
- Both Windows x64 packages were generated by the successful Windows CI run. Downloaded archives passed zip integrity checks and contained the executable and current Claude bridge.

Independent code review identified malformed Claude snapshots replacing valid readings and custom status-line input handling. Both were reproduced with failing regressions and fixed. Review of narrow high-DPI displays also led to proportionally fitting the widget within its monitor; geometry regression passes. Testing repeated reports additionally found and fixed PowerShell's empty-string coercion of the atomic replacement backup argument.

The self-contained zip is approximately 68 MiB; the framework-dependent zip is approximately 113 KiB and requires .NET 10 Windows Desktop Runtime x64. Neither package's size is a claim about runtime memory. The Codex app-server process adds its own resource use.

Interactive taskbar stacking, tray input, mixed-DPI transitions, monitor unplugging, resume behavior, and actual idle resource footprint have **not** been manually verified on a real Windows desktop. Follow [the smoke checklist](manual-smoke-test.md). Native automated checks establish basic API behavior, not every interactive scenario.
